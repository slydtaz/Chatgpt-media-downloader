# v5.0.0 — Atualizações seguras e reparo da instalação

## Atualizador do aplicativo

- O app consulta as Releases públicas do GitHub e compara a versão disponível com a versão instalada.
- Para instalações de código-fonte, também pode comparar a versão presente na branch `main` quando ainda não existir uma Release mais nova.
- A consulta não baixa o pacote completo em segundo plano. O download começa apenas depois que a pessoa confirma a atualização.
- A janela de confirmação exibe a versão e as notas da versão, com opção para continuar usando a versão atual.
- A caixa "Abrir o aplicativo automaticamente depois de atualizar" vem ativada por padrão e a preferência é salva.
- O executável é baixado para uma pasta temporária e sua soma SHA-256 é validada antes da substituição.
- A atualização aguarda o processo atual fechar, usa uma troca transacional e tenta restaurar o backup se a substituição falhar.

## Reparo completo

- A página **Atualizações** inclui **Reparar todos os arquivos**, que baixa novamente a fonte oficial e prepara uma instalação completa.
- Falhas críticas da interface e falhas durante a inicialização oferecem o reparo, sem apagar as pastas pessoais de configuração e mídia.
- No modo fonte, ferramentas externas já baixadas para a pasta `tools` são copiadas para a nova instalação; a configuração fica em APP_DATA.
- A troca não prossegue se o pacote ZIP contém caminhos inseguros, se faltam arquivos essenciais ou se o Product ID não corresponde ao aplicativo.

## Informações e testes

- A página Atualizações apresenta a versão atual, a versão disponível, a origem do pacote e notas.
- Versão interna do projeto: `5.0.0`.
- Testes: `python -m py_compile app/*.py packaged_entry.py` e `python -m unittest discover -s tests -v`.

## Limites conhecidos

- Atualização de executáveis empacotados exige uma Release estável que publique `ChatGPTMediaDownloader.exe` e `SHA256SUMS.txt`. O workflow de release do repositório gera esses arquivos para Windows.
- Instalações em código-fonte usam um helper do sistema para trocar a pasta depois que o processo atual termina. Permissões insuficientes podem impedir a troca; neste caso, os arquivos atuais devem permanecer e a falha será mostrada.
- A verificação HTTPS e SHA-256 reduz o risco de pacote truncado ou adulterado, mas não equivale a uma auditoria independente ou assinatura de código.
