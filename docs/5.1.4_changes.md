# Hotfix 5.1.4 — diagnóstico de inicialização

## Problema tratado

Quando um EXE de janela (sem console) falha antes de a interface gráfica aparecer, o Windows pode mostrar apenas o cursor ocupado por um instante e depois encerrar o processo. Sem um traceback, não é possível afirmar qual falha específica ocorreu no computador afetado.

## Alterações

- O ponto de entrada do executável agora importa o bootstrap dentro de uma proteção de erro. Falhas de importação ou exceções não tratadas são registradas mesmo antes do logger principal da aplicação ser inicializado.
- O diagnóstico tenta gravar em `%LOCALAPPDATA%\ChatGPT\MediaDownloader\logs\startup-fallback.log`; se a pasta não estiver acessível, tenta também `%TEMP%\ChatGPTMediaDownloader-startup.log`.
- Em caso de exceção inesperada, tenta mostrar uma mensagem nativa do Windows com o erro e o caminho do log, sem depender da inicialização do Tkinter.
- São adicionados testes unitários para inicialização normal, exceção no bootstrap e fallback de gravação.
- A versão do aplicativo é atualizada para 5.1.4.

## Limite da correção

Esse hotfix melhora a captura e a apresentação de falhas que escapam do bootstrap; ele não demonstra, sozinho, a causa exata do encerramento observado em uma máquina específica. Se o executável ainda não abrir, o arquivo `startup-fallback.log` (ou o log principal `app.log`) deve fornecer evidências concretas para a próxima correção.
